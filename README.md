Создание базового интерфейса, состоящего из трех страниц. Первый для просмотра список услуг(отели, товары, рейсы и тд) в виде карточек (плиткой в ​​2-4 столбца) с наименованием, ценой (датой рейса, мощностью устройства и т.д.) и картинкой, а также элементом-карточкой потока заявки(корзина) с указанием услугв ней. Это количество хранится в контроллере-обработчике. При клике по карточке происходит переход на вторую страницу с подробной информацией об услуге(даты, описание и тд). А при нажатии на текущую заявкупо ее идентификатору открывается страница просмотра состава заявки, в которой есть поля самой сущности заявки, поэтому она услугаотображает ниже отдельную карточку друг под другом, поля услугивыводятся вправо вправо в 1 символ и справа для каждого из них поля м-м(количества/порядка/главный/комментарий/другое), которые в примере данных нужно изменить пользователь. Также в заявкеили еще в одном поле м-мдолжен быть результат вычисления поля (пока указано готовое значение).

В headerприложения добавьте только кнопку/значок Домой, она для навигации по странице услуг. Добавьте поле ввода для фильтрации контура услугпо одному из полей (название, цена, дата событий), отображаемых на странице (по умолчанию отображать все). Поле хранения необходимо сохранить после запроса. Всего в приложении должно быть 3 запроса GET и две коллекции моделей. Все данные для этих страниц необходимо брать сразу из двух коллекций (массива услуг и словарных заявок), без использования БД. Никаких массивов внутри отдельно услуги(соблюдать атомарность и 1НФ), но можно и нужно писать большие текстовые описания. Никакого редактирования, только поиск и просмотр. БезJavaScript
