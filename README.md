Лабораторная 2
Цель работы : разработка структуры базы данных и ее подключение к бэкенду.
Порядок показа : показать формулу для расчета результата, показать панель администратора adminer, в которую добавить новые услугу, просмотреть данные через selectБД. Показать 3 страницы приложения: зарядить поиск, удалить заявку, перейти по urlудаленной заявки, добавить две услуги в заявку (изменение карточек корзины), критерии заявок. Показать в запросе БД результаты логического удаления и новую заявку. В БД измените поля по теме заявкеи м-мпокажите их в приложении. В коде показать модели, составной уникальный ключ м-м, 4 контроллера через ORM, удаление заявки через SQL UPDATE.
Контрольные вопросы : виды БД, запросы SQL, выбросы, ORM, модель и перенос, чистая архитектура.
ER-диаграмма : сделать в StarUML; таблицы, связи, столбцы, типы столбцов и их длина, первичные, внешние ключи
Задание : Создание базы данных PostgreSQLпо теме работ, подключение БД к создаваемым трем шаблонам.
Необходимо разработать структуру БД по выбранной теме и реализовать ее с учетом требований, изложенных ниже. Используйте таблицу услугна страницах разработанного приложения. Наполнить таблицу данными БД через Adminer.

Получение и поиск услуг, добавление услугив текущую заявку(статус черновик она же "корзина"), а также просмотр это заявкисделать через ORM. Для текущей страницы заявкидобавьте кнопку логического удаления заявки(статус меняется на удаленное) с помощью выполнения SQL-запроса UPDATE, без ORM. Всего пять HTTP-методов: три GET и один POST-добавление в заявку через ORM, еще один POST для удаления заявок через SQL.

При переходе заявкив статус черновик у пользователя, она появилась только при добавлении услугив заявку. Если такое заявкауже есть, то услугадобавиться сразу в нее. Удаленные запросы невозможно, если у пользователя нет текущей информации заявки, ее карточка на странице услуги не активна.

Требования к БД :

Обязательно наличие 4 таблиц (каскадное удаление запрещено!):

услуг(наименование, описание, статус удаленных/руководителей, URL к изображению Nullable, поля по предметной области)
заявок(всего 4 поля NotNull: id, статус, дата создания datetime, создатель; формирование даты (2 создателя) datetime, дата выполнения (2 действия модератора) datetime и модераторполя по предметной области действия).
м-м заявки-услуги(составной уникальный ключ, дополнительное количество полей/порядка/другое)
пользователей
Обязательно наличие 5 или более статусов заявок: черновик, удален, сформирован, завершён, отклонён. У каждого пользователя не более одной задачи в статусе черновик. Названия таблиц и их полей должны соответствовать предметной области. Одно из доп. полей заявкиили м-мрассчитывается при завершении заявки.
